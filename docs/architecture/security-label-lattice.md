# Security-label lattice and container contract

Status: **Phase 0 baseline with pre-consumer corrections proposed by ADR-0002 and ADR-0006**
Requirements: `CLS-001`–`CLS-008`

The `SecurityLabel` fields are fixed in OWGP. Profile sources are versioned and validated by [the profile schema](../../policies/security-label-profiles/profile-v0.1.schema.json); the release pipeline MUST materialize and verify a signed bundle at `RG-08-SECURITY`. [ADR-0006](../adr/0006-signed-policy-bundle-distribution-and-activation.md) proposes the exact activation-set signature profile and replaces the provisional `sigstore-bundle` schema value only upon its required approval. Commercial and US-government-oriented profile sources enumerate their categories/subcategories, compartments, dissemination controls, releasability groups, and export-control rules. Phase 0 records this signing contract and does not fabricate a key ID, digest, or signature before a release candidate exists.

Effective label is the least upper bound of source, explicit, container, and handling inputs under the selected profile. Sensitivity takes the profile maximum; restriction-valued handling, category, compartment, dissemination, and export coordinates compose by union; the allowed-audience `releasable_to` coordinate composes by intersection. An empty semantic permitted-audience intersection, or any contradictory, unknown, cross-profile, or otherwise unrepresentable result, denies. Empty restriction sets and an explicitly empty `releasable_to` input retain their profile-defined neutral meanings before composition. This audience-intersection wording is the project-owner-controlled pre-consumer correction proposed by [ADR-0002](../adr/0002-security-label-algebra-and-profile-identifiers.md); acceptance of that ADR supersedes the Phase 0 shorthand that grouped releasability with union-composed restrictions. No derivation can lower a source.

Repositories, tracker repositories, docs repositories, package namespaces, runner pools, caches, artifact stores, backup sets, and deployment domains are enforcement containers. Per-item markings cannot grant finer read access than a cloneable/provider container. Different access, classification, compartment, retention, or lifecycle requires a separate container.

Deployment security domains use [a machine-readable profile](../../policies/deployment-domains/domain-profile-v0.1.schema.json) to bind a classification ceiling to allowed label profiles, integrations, notification channels, storage/residency, backup domains, runner pools/images, and network egress policy. Inputs outside that declared domain deny.

Lowering/declassification/decontrol is denied by default, requires authority and written reason, is audited, invalidates caches/search/notifications/exports, triggers reconciliation, and uses two-person approval under the government profile. Core Stead performs no cross-domain/write-down transfer.

Profile upgrades run lattice property tests, full decision tables, signature verification, derived-resource recalculation, non-disclosure checks, and rollback rehearsal. A profile cannot claim compliance, accreditation, or FIPS validation merely because the deployment can select validated cryptographic modules.
