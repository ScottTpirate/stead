# Deployment and lifecycle profiles

Supported installation profiles are `local`, `kubernetes-standard`, `enterprise-external-services`, and `high-assurance-airgap`. Docker/Compose and Helm/Kubernetes are first class; no public cloud or SaaS control plane is required. Installation topology is independent of the active security-label policy profiles and deployment security-domain policy: neither a topology name nor a label-profile ID changes authorization behavior.

Effective configuration fixes each permitted label profile/version and its profile-qualified ceiling, trusted identity/attribute authorities, approved signed bridges, integrations, storage/encryption/residency, notification channels, runner pools, network zones and egress, policy activation material, assurance/signing/custody requirements, versions/digests, and backup destinations without exposing secret values. The normative security-domain shape and starter/reference values are [machine-readable](../../policies/deployment-domains/domain-profile-v0.1.schema.json). The reference files are not exhaustive security requirements or product modes.

Upgrade order is detect → compatibility preflight → consistent backup → expand migrations → safe component order → smoke/golden/security tests → report → contract when safe. Rollback is permitted while schemas remain backward compatible; otherwise an explicit tested forward-recovery plan is required. High-assurance air-gap inventory is signed and no-network tested. Core Stead provides no built-in cross-domain or write-down path.
